# 系统原型功能设计方案：人员简历画像绘制与人员分析平台

## 1. 数据模型与要素定义 

在进入页面设计前，首先定义系统底层的**核心字段**，这将支持“高级搜索”和“简历绘制”功能。

- **基础信息：** 姓名 (中/英), 军衔 (Current Rank), 职务 (Current Duty),现任单位,家庭成员, 照片 (Photo).
- **基本情况**：文本介绍.
- **履历时间轴 (Assignments)：** 起止时间, 职位, 单位 (Unit), 地点 (Location).
- **教育背景 (Education)：** 时间, 学位, 学校 (School), 专业.
- **飞行经历 (Flight Info)：** 等级 (Rating), 总飞行时长 (Flight Hours), 战斗时长
-  **机型 (Aircraft Attributes)** (e.g., MC-130H, T-37).
- **联合岗位经历 (Joint Assignments)：** 特定联合岗位的记录.
- **勋章与荣誉 (Awards)：** 列表形式.
- **晋升记录 (Promotions)：** 军衔变动时间轴.
- **性格分析：** 性格特点.
- **作战指挥风格**： 指挥风格.
- **其他备注信息**：文本



历史简历、



## 2. 功能模块详细设计

### 模块一：首页 (Dashboard)（导航与入口）

**布局：** 左右分栏结构。

- **左侧：人员导航栏**
- **排序方式：** 按姓氏首字母 (A-Z) 排序的垂直列表。
- **交互：** 鼠标悬停显示简要信息（姓名+现任职务），点击跳转至详情页。
- **搜索框：** 顶部的快速名字检索框。
- **右侧：数据与入口**
- **数据概览卡片：**
- `人员总数` (数字+环比增长趋势)
- `涉及单位总数` (数字)
- `已生成画像报告数` (数字)
- **功能入口 (宫格图标)：**
- [简历绘制]、[信息查询]、[群体分析]、[维护更新]、[用户管理] (根据权限动态显示)。
- **最新动态列表：** 显示最近更新的人员简历或新生成的分析报告。

### **模块二：人员详情中心 (Individual Profile Center)** （作为所有查询、搜索、绘制功能的“落脚点）

#### 1. 页面定位与交互逻辑

- **定位：** 它是人员全要素数据的“集大成者”，是用户获取个人信息的最直接窗口。
- **入口逻辑：**
  - **首页搜索/导航：** 直接跳转。
  - **群体分析/高级检索：** 点击列表中的姓名，以**侧滑抽屉 (Drawer)** 或 **新标签页** 形式打开，方便用户在对比时快速查看细节。
- **核心功能：** 既要展示静态的结构化数据（履历、飞行时长），也要展示的软性分析结果（性格、指挥风格）。

### 模块三：简历绘制板块 (生产工具)

**流程设计：** 采用分步向导式 (Wizard) 界面。

**Step 1: 基础框架信息录入**

- **输入：** 输入目标人物姓名（如 "Shane S. Vesely"）。
- **系统动作：** 自动匹配库中已有的基础字段（a. 基本框架信息），展示在界面左侧供用户确认。

**Step 2: 多源数据聚合 (素材勾选区)**
此页面分为三个并列的展示区域，每个区域内的条目带有**复选框 (Checkbox)** 和 **[预览]** 按钮。

- **b. 镜像新闻搜索：**
- 输入关键词自动通过API搜索外部新闻源。
- 展示：标题、来源、摘要、发布时间。
- **c. 知识库关联：**
- 系统内部数据库检索（如：该人员所在的部队历史背景、机型技术参数等）。
- **d. 用户自主上传：**
- 该用户自主手动上传的PDF、Word文档或文本片段。

**Step 3: 大模型生成配置**

- **模板选择：** 下拉菜单选择报告模板（例如：标准简历模板、作战能力评估模板、晋升潜力分析模板）。
- **指令微调：** 用户可输入特定Prompt（例如：“重点分析其在特种作战司令部的任职经历”）。
- **生成动作：** 点击 **[大模型编写响应]**。系统将Step 1和Step 2中**已勾选**的所有文本作为Context（上下文）发送给大模型。

**Step 4: 结果编辑与交付**

- **双屏编辑器：** 左侧为生成结果（Markdown/富文本），右侧为用户勾选的所有原始素材。
- **手动修订：** 用户可对AI生成的内容进行增删改。
- **操作：** [保存到档案]、[下载PDF/Word]。

布局逻辑： 顶部进度条，主体分步内容。

### 模块三：信息查询板块 (检索工具)

**布局：** 。

**1. 高级搜索过滤器 (Advanced Filter)**

- **基本字段：** 姓名 (支持模糊搜索)、现任职务。
- **属性字段 (下拉/范围选择)：**
- **教育：** 输入学校名 + 时间段 (Start Year - End Year)。
- **现任单位：** 下拉选择或输入。
- **历任单位：** 输入单位名 + 任职时间段。
- **军衔：** 多选 (e.g., Colonel, Major)。
- **飞行经历：**
- **机型** ：复选框 (e.g., C-130, F-16, MC-130J)。

**1.1. 结果处理**

- **列表展示：** 姓名 | 军衔 | 现任单位 。
- **深度分析交互：**
- 用户在列表中勾选多名人员 (例如：勾选 5 名有过 "Special Operations Wing" 经历的人员)。
- 点击底部悬浮按钮 **[深度分析]**。
- **弹窗/跳转：** 生成一份对比分析报告，指出这些人员的共同特征、履历交集等。

**2.AI智能问答(Text2SQL)**

- **语义解析引擎**： 利用大模型将非结构化的自然语言（如“找一下飞过C-130且有联合岗位经历的中校”）转化为标准的SQL查询语句。

- SQL透明化： 在界面展示生成的SQL语句，允许具备SQL能力的用户进行微调，确保查询过程可追溯、可信。

- 回答合成： 大模型不仅展示查询到的数据表，还会针对查询目标进行“总结性陈述”，直接回答用户问题。
  
  布局逻辑： 上部折叠式筛选器，下部数据表格。

**3.知识图谱**

**功能定义：** 该子模块用于挖掘人员与人员、人员与单位、人员与事件之间的隐性关联。

- **节点定义 (Nodes)：** 人员 (圆形)、单位 (方形)、学校 (菱形)、联合作战经历 (三角形)。
- **边定义 (Edges)：**
  - *同事关系* (Co-worker): 在同一单位服役过。
  - *同窗关系* (Alumni): 毕业于同一院校。
  - *经历同构* (Experience): 参加过同一次联合战役。
- **交互操作：**
  - **点击节点：** 侧边栏弹出该节点的详细卡片。
  - **路径探索：** 选中两个人，系统自动计算并高亮两者之间的“最短关联路径”。
  - **过滤：** 只看“工作链”或只看“同窗网”或经历。

### 模块四：单位群体分析板块（分析工具）

**核心逻辑：** 以“现任单位”为维度的聚合分析。

**1. 单位选择与分类**

- **导航：** 左侧为单位组织架构树 (Tree View)。
- **分类展示：** 点击某单位（如 "HQ Pacific Air Forces"），右侧展示该单位下所有人员的卡片列表（按职务高低排列）。

**2. 多角度分析定义 (自定义维度)**

- **分析配置面板：**
- **选择分析角度 (由业务人员定义)：** 提供复选框，例如：
- [角度A] 晋升速度分析 (根据晋升时间计算平均值)
- [角度B] 院校派系分析 (统计毕业院校分布)
- [角度C] 实战经验分析 (统计Combat Hours和部署经历)
- [角度D] 联合作战背景 (统计Joint Assignments比例)

**3. 分析报告展示**

- **可视化图表：** 饼图 (机型分布)、柱状图 (年龄/军衔结构)、折线图 (单位人员变动趋势)。
- **AI 综述：** 页面底部由大模型生成该单位的战斗力/人员构成总结段落。

核心逻辑： “组织架构树” + “多维数据看板”。左侧选择单位，右侧展示该单位的聚合画像

### 模块五：人事变动预警模块 (HR Alert)（信息更新预警工具）

设计思路： 这是一个待办工单流界面。

- 多源数据监测： 后台定时轮询内部新闻网站API或扫描指定FTP目录下的文件。
- 异动提取逻辑： 大模型提取文本中的关键要素（时间、人名、原职务、新职务、变动类型），并与库内数据（personnel_basic）进行比对。
- 闭环处理机制： 预警信息标记为“待处理”和“已处理”。点击“处理”后，系统自动填充修改表单，并在处理完成后记录审计日志（处理人、时间）。

```

|  [ 人事变动预警 ]        今日扫描：145条  发现变动建议：3条  待处理：2条 |
+-----------------------------------------------------------------------+
|                                                                       |
|  +-----------------------------------------------------------------+  |
|  | [预警条目 1]  来源：内部新闻网站  日期：2026-01-07               |  |
|  | --------------------------------------------------------------- |  |
|  | [原始文本片段] "...任命 Col Shane S. Vesely 为 XXX 司令..."      |  |
|  | [AI 解析建议]                                                   |  |
|  | - 识别人员：Shane S. Vesely (ID: 1001)                          |  |

|  | --------------------------------------------------------------- |  |
|  | [忽略]                         [ 点击处理 (跳转至维护更新页) ]  |  |

```

### 模块六：维护更新板块（信息手动更新工具）

**权限：** 仅管理员及以上可用。

**功能列表：**

1. **人员信息全库管理：** 表格形式展示所有人员，支持 [新增]、[编辑]、[删除]。

- *编辑详情：* 结构化录入 Resume 的所有字段 (JSON结构对应表单)。

2. **素材管理：**

- **历史报告上传：** 批量上传旧版PDF报告，系统自动OCR并归档到对应人员名下。
- **用户上传管理：** 查看和清理用户在“绘制板块”上传的临时文件。

3. **数据清洗：** 提供工具合并重复人员（例如 "Shane Vesely" 和 "S. Vesely"）。

核心逻辑： 这是一个典型的后台管理界面（CRUD），强调数据的准确性和素材的归档管理。建议采用 Tab页签 切换不同维护任务。

### 模块七：用户管理权限模块

**权限矩阵设计：**

|角色|简历绘制|信息查询|群体分析|维护更新|用户管理|操作日志|
|--|--|--|--|--|--|--|
|**基础用户**|✅|✅|✅|❌|❌|❌|
|**管理员**|✅|✅|✅|✅|❌|❌|
|**超级管理员**|✅|✅|✅|✅|✅ (分配权限)|✅|

**功能点：**

- **权限分配：** 超级管理员可勾选用户的角色。
- **操作日志：** 记录“谁”在“什么时间”对“哪个人员”进行了“查询/导出/修改”操作（保障数据安全与合规）。

<br/>

核心逻辑： 仅超级管理员可见，用于分配角色（RBAC模型）和审计安全日志。
